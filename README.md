# 📊 E-commerce Churn Intelligence

**End-to-end Customer Retention Decision Engine combining churn prediction, customer lifetime value estimation, next-best-action decisioning, ROI simulation, explainable machine learning and grounded LLM recommendations.**

The project goes beyond predicting which customers may churn. It converts model outputs into customer-level retention decisions that can be explored through an interactive Streamlit application.

---

## 🚀 Project Overview

This project builds a complete customer retention decision system using transactional e-commerce data.

The system answers six practical business questions:

* Which customers are at risk of churn?
* Which customers have the highest predicted value?
* Which customers should be prioritized for retention?
* What retention action should be taken?
* Is the proposed intervention financially justified?
* How can the model recommendation be explained to a business user?

The solution combines traditional machine learning with business decisioning and an optional generative AI layer.

A leakage-safe snapshot methodology ensures that customer features are created only from information available at prediction time.

## 🧠 Business Problem

Customer churn prediction alone does not answer the most important retention question:

> **What should the business do with the prediction?**

A customer can have high churn probability but relatively low economic value. Another customer may have moderate churn probability but very high predicted lifetime value.

The system therefore combines:

```text
Churn Risk
    +
Customer Value
    +
Model Explanation
    +
Retention Strategy
    +
Campaign Economics
    =
Retention Decision
```

This creates a decision-support layer on top of the predictive model.

## 🕒 Leakage-Safe Snapshot Methodology

A key design principle of the project is preventing target leakage.

Reference date:

```text
2011-12-09 12:50
```

Prediction snapshot:

```text
2011-09-10 12:50
```

Prediction horizon:

```text
90 days
```

Customer features are calculated using transactions available **before the snapshot date**.

Churn labels are then determined using customer activity in the future prediction window.

Dataset statistics:

```text
Transactions:          397,884
Historical records:    236,358
Customers:               3,370
Churn rate:              ~43.0%
```

This simulates a realistic situation in which the model must make a prediction without access to future customer behavior.

## 🧩 Feature Engineering

Customer-level features include RFM-style variables and behavioral activity windows.

Examples include:

* recency
* order frequency
* total monetary value
* average and median order value
* orders in the last 30 / 60 / 90 days
* spend in recent activity windows
* purchasing activity trends

These features create a behavioral snapshot for each customer at prediction time.

## 💰 Customer Lifetime Value

The system estimates customer value and combines it with churn risk.

The retention priority score is:

```text
priority_score = churn_score × predicted_clv
```

This prevents retention strategy from being driven by churn probability alone.

A high-value customer with meaningful churn risk can therefore receive higher priority than a lower-value customer with similar risk.

## 📊 Value vs Risk Segmentation

![Value vs Risk Matrix](outputs/value_risk_matrix.png)

Customers are segmented according to predicted value and churn risk.

Examples:

* **High Value + High Risk** → immediate retention attention
* **High Value + Medium Risk** → proactive personalized intervention
* **High Value + Low Risk** → loyalty strategy
* **Low Value + High Risk** → lower-cost retention approach

The segmentation layer connects predictive analytics with business strategy.

## 🎯 Next Best Action

The decision engine assigns a recommended retention action according to customer segment.

| Segment                | Recommended Action |
| ---------------------- | ------------------ |
| HIGH_VALUE_HIGH_RISK   | offer_discount     |
| HIGH_VALUE_MEDIUM_RISK | personal_offer     |
| HIGH_VALUE_LOW_RISK    | loyalty_program    |
| MEDIUM_VALUE_HIGH_RISK | email_campaign     |
| LOW_VALUE_HIGH_RISK    | low_priority       |
| Other                  | no_action          |

The recommendation layer is extended with communication channel and timing.

### Example

| Segment                | Action          | Channel    | Timing |
| ---------------------- | --------------- | ---------- | ------ |
| HIGH_VALUE_HIGH_RISK   | offer_discount  | email      | 24h    |
| HIGH_VALUE_MEDIUM_RISK | personal_offer  | sales_call | 48h    |
| HIGH_VALUE_LOW_RISK    | loyalty_program | app        | 7d     |

The result is a customer-level retention plan rather than only a churn probability.

## 💸 Campaign ROI Simulation

The project estimates the economics of each proposed retention action.

For every customer, the system calculates:

* campaign cost
* expected retained value
* expected profit
* estimated ROI

Current simplified decision formulas:

```text
expected_retention_value = predicted_clv × churn_score

expected_profit = expected_retention_value - campaign_cost

estimated_roi = expected_profit / campaign_cost
```

Example campaign assumptions:

| Action          | Cost |
| --------------- | ---: |
| offer_discount  |  200 |
| personal_offer  |  120 |
| loyalty_program |   60 |
| email_campaign  |   20 |

These values are simulation assumptions rather than measured campaign outcomes.

The ROI layer is intended to demonstrate how model predictions can be incorporated into a business decision framework.

## 💡 Business Explanation Layer

Each customer receives a deterministic business explanation generated directly from pipeline outputs.

Example:

```text
Customer 12346 is classified as HIGH_VALUE_HIGH_RISK.
Reason: High value and high churn risk.
Recommended action: offer_discount via email within 24h.
Churn risk score is 1.00 and predicted CLV is 6317.
Expected profit is 6117 with estimated ROI of 30.58.
```

This layer provides a transparent explanation even when the optional LLM integration is not used.

## ✨ Grounded LLM Recommendation Layer

The project integrates the OpenAI API to generate concise retention recommendations for individual customers.

Before an API request is made, the pipeline creates structured customer context containing:

* customer segment
* churn score
* risk drivers
* protective drivers
* model explanation
* predicted CLV
* priority score
* recommended action
* channel
* timing
* campaign cost
* expected profit
* estimated ROI

The LLM is explicitly instructed not to:

* invent customer behavior
* infer unsupported feature direction
* infer causality from model contributions
* invent currencies
* present modeled outcomes as guaranteed results

The LLM therefore acts as a **business explanation layer on top of existing analytical outputs**, rather than as the source of the retention decision.

API requests are generated **on demand** from the Customer Explorer to avoid unnecessary API usage.

## ⚠️ Modeling Limitations

This project is a portfolio decision-support system built on historical transactional data.

Important limitations include:

* campaign costs are simulated assumptions
* expected profit and ROI are modeled estimates, not observed campaign outcomes
* recommended actions have not been validated through randomized retention experiments
* CLV estimates depend on historical customer behavior
* customer segmentation uses predefined business rules
* model performance may change under future data drift
* LLM recommendations depend entirely on analytical context supplied by the pipeline

In a production environment, the next step would be to validate retention strategies through controlled experiments and monitor model and business performance over time.
